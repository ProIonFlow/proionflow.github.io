14 · Time & timezone

TOU windows are defined in the tariff's local prevailing time — the utility's service-territory zone, not the customer's phone. A one-hour error would shift load into peak, causing real financial harm and a false savings claim. Derive it, confirm it passively, ask only when genuinely ambiguous.

Resolution order
  1. Utility service territory — most are single-zone (Dominion → Eastern); confirming the utility usually settles it outright.
  2. ZIP narrows it where a utility spans zones.
  3. Device zone as a silent cross-check (Intl…resolvedOptions().timeZone, no prompt). If it matches a candidate, take it and say nothing.
  4. Ask only if ambiguity remains — some ZIPs straddle two zones. A conditional question, consistent with never asking what can't change an outcome.
Passive confirm (rate step)
Times shown in Eastern Time · change

Shown as an editable fact — one tap to correct, no question for the unambiguous 95%. Also editable later in Settings → Rate/utility, since it's effectively a quiz answer.

Two implementation rules
  • Store the IANA zone (America/Phoenix vs America/Denver), never an offset or abbreviation. Arizona is the trap: most of the state skips DST, the Navajo Nation observes it, and the Hopi Reservation inside that doesn't — an offset breaks twice a year.
  • Any time shown against a tariff is labelled in service-territory local time. The device zone is used only for display convenience and notification timing.

Screen-reader utilities

Visually-hidden text for screen readers uses the canonical .pif-sr class (define once per file):

.pif-sr{position:absolute;width:1px;height:1px;
  padding:0;margin:-1px;overflow:hidden;
  clip:rect(0,0,0,0);white-space:nowrap;border:0}

The “≈” rule: any “≈” prefixing a figure must be <span aria-hidden="true">≈</span><span class="pif-sr">approximately </span> so it reads “approximately $5.44”, or use plain words (“about $42”) where there’s room.

17 · Responsive

Layout scaffolding lives in a small set of helper classes so every batch (and Batch 9) shares one breakpoint system. This is the single source of truth — copy the block verbatim; component styling stays inline as always, only structural layout is class-driven.

Breakpoints

Two stops, mobile-tolerant desktop-first. ≤768px — tablet/phone: columns stack to one, the primary nav collapses to a hamburger dropdown (.pif-hamburger + .pif-nav.open), primary buttons go full-width. ≤480px — tightens shell padding only. No horizontal page scroll at 390px is the acceptance test. Source order matters: the .pif-hamburger base (display:none) must be declared before the @media (max-width:768px) block — equal specificity means the later-declared rule wins, so a base placed after the media query would keep the hamburger hidden at all widths.

Helper classes

.pif-page — the centered page container (replaces the inline max-width;margin:0 auto;padding). .pif-col-2 / .pif-col-3 — grids that auto-stack ≤768px. .pif-nav — top nav, scrolls instead of overflowing. .pif-btn-full — full-width primary buttons ≤768px.

Menus & wide content: the account dropdown and launcher fan cap at max-width:calc(100vw - 28px), right-anchored, so they never overflow. Wide tables/rows get overflow-x:auto on their own container — never let a child break the page. Charts stay %/flex-width, never fixed px.
